# 双端项目架构说明

## 1. 系统定位

本仓库不是单一网页，也不是单一 Android 检测 App，而是：

- **后端**：统一分析与案件编排中枢
- **网页端**：总览、证据链、案件库展示端
- **Android 端**：移动协同查看与举报辅助端

## 2. 三层分工

### 后端
- 演示视频抽样分析
- 智谱视觉识别
- 时序融合生成事件
- 按案件归档
- 生成 15 秒证据片段
- 生成正式举报文书

### 网页端
- 展示总览指标
- 展示事件列表
- 展示案件库
- 展示证据图、证据片段和文书
- 作为统一浏览与操作入口

### Android 端
- 连接同一 FastAPI 后端
- 查看案件列表
- 查看案件详情、片段与文书
- 发起移动端案件举报
- 作为移动协同处理入口

## 3. 与参考 Android 原型的关系

`newnew` 里的文档和旧 Android 原型说明了另一条路线：

- CameraX 实时采集
- JNI + ncnn / YOLO 端侧检测
- HyperLPR 本地识别
- Room 案件管理

本仓库没有直接复刻那条高耦合端侧检测链，而是吸收其**案件化闭环**与**模块化表达**，将其转化为当前双端协同项目结构。

## 4. 当前架构价值

这种结构比单端原型更完整，能够同时体现：

1. 视频分析链；
2. 事件 -> 案件 的数据组织；
3. 证据片段与正式文书；
4. 网页端与 Android 端的角色分工；
5. 从参考原型到当前项目结构的演进过程。
